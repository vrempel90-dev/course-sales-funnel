# Course Sales Funnel — Telegram Admin Panel

Node.js 22+, TypeScript, grammY, PostgreSQL, Prisma и Zod. Административная работа выполняется в личном чате Telegram через `/admin`.

Текущий scope: только Telegram Admin Panel. Клиентский `/start`, анкета, каталог, checkout, приём чеков, клиентские рассылки/напоминания, Instagram, Meta, сайт и web-admin не реализованы. Для будущего клиентского этапа подготовлены данные, переводы, сегменты, настройки и события.

## Установка и первый запуск

1. Создайте бота у BotFather командой `/newbot`, получите токен.
2. Установите Node.js 22+ и PostgreSQL. Для локальной БД можно выполнить `docker compose up -d`.
3. Скопируйте `.env.example` в `.env` и заполните значения.
4. Выполните:

```sh
npm ci
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
npm run build
npm start
```

Разработка: `npm run dev`. Команды `db:generate`, `db:migrate`, `db:seed` оставлены как совместимые aliases.

`OWNER_TELEGRAM_ID` — ваш числовой Telegram user ID, например `123456789`, а не username, ID бота или ID учебного канала. Используйте значение `from.id` своего Telegram update или известный вам доверенный способ определения собственного ID. Первый запуск/seed создаёт OWNER в PostgreSQL. Права после этого проверяются по БД. Повторный запуск не сбрасывает существующие роли и отключённые записи. Legacy ADMIN повышается до OWNER при bootstrap только если в БД ещё никогда не было OWNER.

Откройте личный чат с ботом и отправьте `/admin`. Числовой ID отправителя должен совпадать с активным `AdminUser`. Без токена запускается только health server; Telegram API не вызывается. С токеном требуется OWNER ID.

## Курсы, тарифы и переводы

`Курсы → Добавить`: категория, название RU, название KZ (можно пропустить), краткое/полное описание RU/KZ, программа RU/KZ, длительность RU/KZ, обложка, демо, канал, статус. Затем предпросмотр с исправлением отдельных полей и подтверждение. Для пропуска nullable поля используйте кнопку или `-`.

`Курсы → карточка → Русский контент / Қазақша контент` редактирует конкретное поле соответствующей translation record. Категория, обложка, демо, канал, статус, active и порядок редактируются отдельно. Архивирование: Статус → ARCHIVED → Сохранить. Направления имеют RU/KZ контент, active и порядок.

`Курсы → карточка → Тарифы → Добавить` создаёт тариф именно этого курса. Альтернатива — главное меню Тарифы → Добавить → выбрать курс. Укажите код (латинские заглавные буквы/цифры/underscore), RU/KZ название, описание, KZT, RUB, active и порядок.

`Тарифы → карточка → Цена KZT / Цена RUB → новая сумма → Сохранить`. Допустимо до двух десятичных знаков; запятая приводится к точке. До подтверждения цена не меняется. AuditLog записывает цены до/после. Уже созданные суммы Payment не пересчитываются.

`Тарифы → карточка → Русский / Қазақша контент` изменяет переводы. `Активность → Нет` отключает тариф. Удаление требует подтверждения: используемый оплатой, зачислением, выбором клиента или историей тариф выключается; свободный удаляется.

Утверждённые KZ маркетинговые переводы заказчиком не предоставлены. KZ seed-записи пустые, отображается «⚠️ Перевод KZ не заполнен», каждое отсутствующее поле использует RU. Заполнить нужно названия/описания категорий, курсов, тарифов, программы/длительность курсов, тексты воронки, названия/описания/кнопки бонусов и описание пробного урока KZ. Runtime AI translation не используется. RU название нельзя очистить; KZ можно очистить для возврата к fallback.

Обложки принимают фото/документ изображения; демо — видео/документ видео. Можно задать HTTP(S) URL. Сохраняются file_id и тип; файлы не скачиваются на Railway.

## Воронка, бонусы и рекомендации

`Воронка продаж → Приветствие / Профессия / Для семьи / Бьюти / Продажа / Напоминания → RU / KZ → запись → Текст / Активность → Сохранить`.

Seed сохраняет оригинальные RU тексты из ТЗ: WELCOME, выбор цели, вопросы/варианты опыта и семейной проблемы, персонализированные beauty ответы, CTA и текст бонуса. Продажа и напоминания подготовлены пустыми и выключенными: их оригиналы в ТЗ не заданы. KZ-тексты редактируются независимо. Эти данные не запускают клиентский сценарий.

Три бонуса: PROFESSIONAL_BASIC_VIDEO — «3 базовых приема массажа, с которых начинает любой профи»; FAMILY_SAFE_CHECKLIST — «5 правил безопасного домашнего массажа, чтобы не навредить»; BEAUTY_SALES_VIDEO — «Как упаковать доп. услугу и продавать её каждому второму клиенту».

`Бонусы → запись → Бонус: Telegram видео / документ / HTTP(S) URL`: отправьте соответствующий файл или ссылку, проверьте предпросмотр, сохраните. Видео, PDF/checklist хранятся по Telegram file_id; доступны просмотр, RU/KZ контент и active. Для смены типа с несовместимым файлом сначала очистите медиа через `-`, смените тип, загрузите новое.

`Рекомендации → Добавить` задаёт primaryGoal, experienceLevel, familyProblem, beautyProfession, legacy category/learningGoal, курс, приоритет и active. ANY хранится как null. Условия объединяются AND. Seed создаёт 16 правил: восемь профессиональных для BEGINNER/HAS_BASIC_EXPERIENCE, три HOME по familyProblem, пять BEAUTY по профессии. Несколько профессиональных курсов остаются допустимыми вариантами; автоматического выбора единственного курса нет.

## Клиенты, статистика и запросы

`Клиенты → Новые / Ждут оплату / Оплатили / Требуют внимания / RU / KZ / Все / Найти клиента`. Поиск принимает имя, фамилию, username, Telegram ID, телефон и работает без учёта регистра. Карточка показывает язык, контакты, сегменты, курс/тариф, этап и даты. Отдельные кнопки открывают оплаты, курсы, доступы, запросы и историю FunnelEvent с пагинацией. При изменении выбранного курса сначала очистите несовместимый выбранный тариф.

Статистика читает реальные данные PostgreSQL: новые клиенты и оплаты сегодня, ожидающие/подтверждённые оплаты, новые запросы, общие счётчики, сегменты primaryGoal/RU/KZ/beauty. Выручка PAID отображается отдельно KZT/RUB. День определяется по Asia/Almaty. Пустая БД работает с нулевыми счётчиками.

`Запросы → Новые / В работе / Закрытые → карточка → Взять в работу / Закрыть / Клиент`. Нельзя забрать запрос у другого ответственного или открыть уже закрытый запрос.

## Оплаты и доступы

`Оплаты → Ждут проверки → карточка → Показать чек / Подтвердить / Отклонить`. OWNER/ADMIN могут проверить PENDING_REVIEW. Approve в одной транзакции сохраняет PAID, reviewedAt/reviewer, Enrollment, FunnelEvent и AuditLog. Существующая защита сохраняет одно Enrollment на user/course; повторное подтверждение не создаёт дублей. Tariff ID переносится в создаваемое зачисление. Противоречащий тариф другого курса отклоняется. Повторная покупка уже активного курса не создаёт второй доступ и не меняет действующий тариф автоматически.

Отклонение: нечитаемый чек, неверная сумма, платёж не найден или другая причина с текстом. Причина и reviewer сохраняются. Ошибка доступа не отменяет PAID.

`Доступы → Ожидают / Ошибки / Выданы / Все → карточка → Повторить выдачу`. Используется course.telegramChannelId и createChatInviteLink: member_limit=1, expire_date из inviteLifetimeHours. Успех — GRANTED, ссылка и время; ошибка — FAILED, безопасное описание и аудит. Клиенту ссылка автоматически не отправляется: администратор видит её в карточке.

Добавьте бота администратором учебного канала с правом приглашения участников. В карточке курса задайте реальный `-100…` Channel ID или @username. Одновременные запросы защищены CREATING. При неоднозначном timeout проверьте инвайты в канале и отзовите возможную незаписанную ссылку до ручной сверки. Активную операцию нельзя обойти; после падения процесса ручная сверка доступна через 10 минут. Действующая GRANTED ссылка повторно не создаётся.

## Администраторы, реквизиты, настройки и статус

OWNER: `Администраторы → Добавить → числовой Telegram ID → имя → ADMIN или MANAGER → язык → подтверждение`. Роль OWNER назначается существующему сотруднику из карточки. Отключение/включение и смена роли требуют подтверждения; последний активный OWNER защищён.

OWNER: `Реквизиты → Казахстан KZT / Россия RUB → название способа, инструкция, реквизиты, включение`. Kaspi/банк РФ заполняются владельцем. Seed создаёт выключенные записи с пустыми реквизитами. Для включения обязательны инструкция и реквизиты.

Настройки: project/support, admin notifications, reminders enabled, задержки неактивности/бонуса/оплаты (default 3 часа), max attempts (default 3), срок инвайта (1–168 часов), expertContact. Для будущего пробного урока/созвона доступны enabled, RU/KZ описания, контакт, nullable booking URL, числовые Telegram ID администраторов через запятую. Клиентский booking/reminder flow не запускается.

Статус системы проверяет БД и реальный getMe, показывает username, uptime, активных администраторов/курсы, окружение и последнюю безопасную ошибку. Значения bot token и DATABASE_URL не показываются.

## Архитектура и миграции

Telegram UI — `src/bot/admin/`, commands/callbacks/keyboards/middleware. Бизнес-логика — `src/services/`; запросы списков/статистики — `src/repositories/`; Prisma client — `src/database/`; словари — `src/i18n/`; HTTP health и durable polling — health.ts/worker.ts.

Основные модели: AdminUser, AdminConversationState, User, CourseCategory, CourseCategoryTranslation, Course, CourseTranslation, CourseTariff, CourseTariffTranslation, RecommendationRule, FunnelContent, BonusMaterial, BonusMaterialTranslation, Payment, Enrollment, ManagerRequest, PaymentMethodSetting, Setting, AuditLog, FunnelEvent, TelegramBotError, Reminder. Legacy sessions/answers/recommendations/outbox и polling tables сохранены, их клиентские обработчики не запускаются.

Миграции:

- 20261003110000_initial — первоначальная схема.
- 20261003180000_telegram_admin — существующая Telegram admin инфраструктура.
- 20261004100000_catalog_localization — языки/сегменты, переводные таблицы, тарифы, воронка/бонусы, настройки модели reminders. Старые тексты копируются в RU translations, цена Course переносится в STANDARD тариф, Payment/Enrollment получают этот tariffId, только затем priceKZT/priceRUB удаляются из Course. Исторические суммы оплат и реквизиты сохраняются.

Legacy RU поля title/description в Course/Category остаются совместимыми зеркалами. Translation records — источник локализованного контента; редактор RU синхронизирует зеркала. Legacy AdminUser без Telegram ID сохранены для миграционной совместимости и не авторизуются в боте.

Мастера хранят payload, шаг, nonce, expiresAt в PostgreSQL. Nonce меняется после каждого шага; повторные update и кнопки не повторяют действия. Подтверждение расходует состояние атомарно. Редакторы проверяют сохранённую revision, поэтому устаревший мастер не перезаписывает изменения другого администратора: откройте редактор заново.

Аудит включает курсы, переводы, категории, тарифы/цены до-после, правила, контент, бонусы, оплаты, доступы, сотрудников/роли, реквизиты/настройки. Ошибки сохраняются в TelegramBotError с редактированием секретов; длинный JSON context остаётся валидным. Stack пользователю не показывается.

Worker сохраняет updates/offset, обрабатывает последовательно и удерживает PostgreSQL lease. Состояние survives restart, локальные файлы для бизнес-данных не используются.

## Health и Railway

Единственный HTTP endpoint — `GET /health`: status, database, telegram configured/not_configured, tokenConfigured, timestamp. При недоступности БД — 503; прочие пути/методы — 404. Веб-интерфейса нет.

1. Подключите репозиторий/нужную ветку к Railway и добавьте PostgreSQL.
2. Свяжите DATABASE_URL с БД; задайте TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_ID, NODE_ENV=production; username необязателен.
3. Dockerfile использует Node.js 22, npm ci и Prisma generate/build. railway.json запускает db:migrate перед развёртыванием, npm start, health /health и ON_FAILURE restart.
4. После миграций выполните `npm run prisma:seed` в окружении контейнера сервиса. Повторный seed сохраняет введённые данные.
5. Проверьте /health, затем личный чат `/admin`, роли и приглашение в реальный учебный канал.

При обновлении существующего сервиса сделайте резервную копию PostgreSQL и разворачивайте миграцию вместе с новой версией worker: старый бинарник ожидает удалённые Course.price поля. Live Railway deployment требует вашего доступа и отдельно проверяется; локальные тесты его не подтверждают.

Проверяет три миграции, 11 legacy-preservation assertions, seed дважды, цены 15 курсов/23 тарифов, RBAC, последний OWNER, callback auth, RU/KZ/fallback, CRUD/редакторы, транзакционные оплаты, access retry, пагинацию, поиск, uploads и устаревшие мастера. Telegram API замещён mock.

`test:http` запускает скомпилированный worker без токена, проверяет health/отсутствие web routes и сохранность мастера после перезапуска. `npm test` без TEST_DATABASE_URL выполняет unit tests; PostgreSQL integration tests пропускаются. Для полной проверки используйте test:integration.

Реальные getMe, UI в Telegram, отправка медиа/чека, права канала и createChatInviteLink требуют действующего TELEGRAM_BOT_TOKEN. Mock не подтверждает эти внешние права. Клиентский flow будет подключаться отдельным следующим этапом к уже подготовленным моделям и контенту.
