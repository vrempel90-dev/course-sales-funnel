# Course Sales Funnel — Telegram Admin Panel

Текущая версия реализует только административный бот на TypeScript, grammY, PostgreSQL, Prisma и Zod. Вход: **/admin** в личном чате с ботом. Веб-интерфейс и клиентские команды отсутствуют. Клиенты, оплаты и запросы отображаются из БД; их приём от клиентов будет отдельной задачей.

## Запуск

Нужен Node.js 22+ и PostgreSQL 16.

1. Скопируйте .env.example в .env.
2. Заполните DATABASE_URL, TELEGRAM_BOT_TOKEN и OWNER_TELEGRAM_ID. TELEGRAM_BOT_USERNAME — необязательный username без токена.
3. Выполните:

```sh
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run build
npm start
```

Для разработки: npm run dev. Локальный PostgreSQL: docker compose up -d.
Seed повторяемый: существующие данные и реквизиты не перезаписываются; пять примеров курсов создаются в DRAFT. Реальных платёжных реквизитов в коде нет.

OWNER_TELEGRAM_ID — ваш **числовой Telegram user ID**, например 123456789, а не @username и не ID канала. Узнать его можно из доверенного источника Telegram ID или поля from.id Telegram update. Не задавайте ID другого человека. При первом запуске бот создаёт OWNER. Seed также выполняет bootstrap. Уже существующие роли и отключённые OWNER при перезапуске не сбрасываются. Для перехода со старой версии настроенный legacy ADMIN становится OWNER только если в БД ещё никогда не было OWNER.

Без TELEGRAM_BOT_TOKEN запускается только health server; Telegram API не вызывается. При наличии токена OWNER_TELEGRAM_ID обязателен.

## ENV

| Переменная            | Назначение                                                          |
| --------------------- | ------------------------------------------------------------------- |
| DATABASE_URL          | PostgreSQL connection string                                        |
| TELEGRAM_BOT_TOKEN    | Токен от BotFather                                                  |
| TELEGRAM_BOT_USERNAME | Необязательный username бота; в статусе используется также getMe    |
| OWNER_TELEGRAM_ID     | Числовой ID первого владельца                                       |
| NODE_ENV              | development / production / test                                     |
| PORT                  | HTTP health server, по умолчанию 3000; Railway задаёт автоматически |
| WORKER_INTERVAL_MS    | Интервал polling цикла, по умолчанию 1000                           |

Платёжные реквизиты, настройки и invite lifetime хранятся в PostgreSQL, а не в ENV.

## Роли и навигация

| Действия                                                  | OWNER | ADMIN | MANAGER |
| --------------------------------------------------------- | ----- | ----- | ------- |
| Статистика, клиенты, чтение курсов/оплат/запросов         | Да    | Да    | Да      |
| Редактирование клиентов и обработка запросов              | Да    | Да    | Да      |
| Курсы, направления, правила, подтверждение оплат, доступы | Да    | Да    | Нет     |
| Сотрудники, роли, реквизиты, настройки                    | Да    | Нет   | Нет     |

В меню показываются доступные разделы. Подделанная кнопка не даёт дополнительных прав: active и роль проверяются при каждой команде, callback и внутри транзакций изменений. Посторонний пользователь получает «Команда недоступна.». Групповые чаты не обслуживаются.

Меню: Статистика, Клиенты, Курсы, Направления, Рекомендации, Оплаты, Доступы, Запросы, Администраторы, Реквизиты, Настройки, Закрыть. В разделах есть Назад и Главное меню. Навигация редактирует существующее сообщение. Списки — по пять записей; пагинация работает в обе стороны. callback_data проверяется на лимит 64 байта.

## Сотрудники

OWNER: /admin → Администраторы → Добавить → Telegram ID → имя → ADMIN или MANAGER → Создать.

Карточка сотрудника позволяет сменить роль и включить/отключить доступ с подтверждением. OWNER можно назначить существующему сотруднику из карточки. Последнего активного OWNER нельзя отключить или понизить. Защита действует и при одновременных запросах. Физическое удаление сотрудников не предлагается.

## Клиенты и статистика

Клиенты: новые, ожидающие оплаты, оплатившие, требующие внимания, все, поиск. Поиск принимает имя, фамилию, @username, числовой Telegram ID и телефон.

Карточка показывает контакты, опыт, направление, цель, выбранный курс, этап и даты. Кнопки открывают оплаты, приобретённые курсы, доступы, запросы и историю FunnelEvent. MANAGER и выше могут редактировать карточку. Раздел доступа доступен OWNER/ADMIN.

Статистика читает PostgreSQL: клиенты всего/сегодня/7 дней/текущий месяц, статусы курсов и оплат, активные зачисления, ожидающие и ошибочные доступы, новые и открытые запросы. Выручка учитывает только PAID и отображается отдельно для KZT/RUB. День и календарный месяц определяются по Asia/Almaty. Пустые счётчики равны нулю.

## Направления и курсы

Направления → Добавить: название, описание (или -), активность, порядок. В карточке каждое поле редактируется отдельно. Вместо удаления используется выключение направления, чтобы сохранять связи.

Курсы → Добавить: 12 шагов:

1. Название.
2. Краткое описание.
3. Полное описание.
4. Направление.
5. Программа.
6. Продолжительность.
7. Цена KZT.
8. Цена RUB.
9. Обложка: фото, документ изображения, HTTP(S) URL или -.
10. Demo: видео, документ видео, HTTP(S) URL или -.
11. Telegram Channel ID (-100…) или @username, либо -.
12. DRAFT / ACTIVE / HIDDEN / ARCHIVED.

После заполнения показывается предпросмотр. Можно изменить поле, создать курс или отменить. Редактирование существующего курса не требует повторного прохождения всех шагов.

Курсы → карточка → Цена KZT / Цена RUB: новая сумма, до двух знаков после десятичной точки → Сохранить.
Demo и обложка редактируются аналогично; Telegram file_id и тип файла сохраняются без скачивания. Документы отправляются как документы. Для архива выберите поле Статус → ARCHIVED. Порядок сортировки доступен в карточке.

Для выдачи инвайтов добавьте бота администратором соответствующего канала и предоставьте право приглашать участников. Channel ID берётся из Telegram, бот не подставляет выдуманный ID.

## Правила рекомендаций

Рекомендации → Добавить: опыт или ANY, направление или ANY, цель или ANY, курс, приоритет, активность. Незаполненное условие означает отсутствие ограничения. Условия объединяются AND. Карточка показывает читаемое правило; доступны изменения отдельных полей и удаление с подтверждением.

В этой версии правила только администрируются. Клиентский подбор курсов не запускается.

## Оплаты и доступы

Оплаты → На проверке / Подтверждённые / Отклонённые / Все → карточка. Карточка содержит клиента, курс, сумму, валюту, страну, метод, статус и даты. Показать чек отправляет сохранённый Telegram file_id.

Подтвердить доступно OWNER/ADMIN только для PENDING_REVIEW. В одной Serializable транзакции сохраняются PAID, reviewedAt, reviewedByAdminId, зачисление и AuditLog. Повторное нажатие не создаёт повторного зачисления или аудита. При повторной оплате того же курса действует уникальная пара userId/courseId.

Отклонить → чек не читается / неверная сумма / платёж не найден / другая причина. Для другой причины вводится текст, затем подтверждение. REJECTED и причина сохраняются с аудитом. После обработки противоречащий переход отклоняется.

Доступы → ошибки / ожидают выдачи / выданные / все → карточка → Повторить выдачу доступа.
Бот вызывает createChatInviteLink с member_limit=1 и expire_date из настройки срока инвайта. Успех сохраняет GRANTED, ссылку и время; ошибка — FAILED и безопасное описание. Доступ в канал **автоматически клиенту не отправляется**. Администратор видит ссылку в карточке.

Одновременные запросы защищены состоянием CREATING. При сетевом timeout результат создания ссылки может быть неизвестен: требуется проверить инвайты канала и отозвать возможную незаписанную ссылку перед кнопкой ручной сверки. Активный запрос создания нельзя обойти сверкой; после сбоя процесса сверка доступна через 10 минут. Неистёкшая GRANTED ссылка повторно не создаётся.

## Запросы, реквизиты, настройки

Запросы → новые / в работе / закрытые → карточка → Взять в работу / Закрыть / Клиент. Уже взятый запрос нельзя забрать у другого сотрудника.

OWNER: Реквизиты → Казахстан KZT или Россия RUB → название способа, инструкция, реквизиты, включение. Kaspi/Сбер заполняются вами; включение требует инструкции и реквизитов. Страны и валюты разделены.

Настройки: название проекта, support username, уведомления администраторам, напоминания, задержка demo/оплаты, срок инвайта 1–168 часов. Уведомления и напоминания сохраняются для будущей клиентской части; сейчас клиентских отправок и scheduler нет.

Технический статус показывает наличие токена без его значения, БД, username, uptime, число активных сотрудников и последнюю безопасную ошибку.

## Мастера, аудит, ошибки

AdminConversationState сохраняет flowType, step, payload, nonce и expiresAt. Срок — один час. После перезапуска процесс может продолжить мастер из БД; /admin начинает меню заново. /cancel и Отмена удаляют состояние. Nonce меняется после каждого шага, старые кнопки и повторные подтверждения отклоняются.

AuditLog содержит actor, action, entityType, entityId и metadata: оплаты, курсы/архив, направления, правила, сотрудники/роли, реквизиты, настройки и выдача доступа. FunnelEvent хранит историю клиента. Ошибки записываются в TelegramBotError с JSON context, типом и безопасным сообщением/stack. Токены и DATABASE_URL редактируются перед сохранением; администратор не получает стек.

## Миграции и health

20261003110000_initial — существующая первоначальная схема.
20261003180000_telegram_admin — OWNER, nullable legacy passwordHash, поля категорий/медиа/сортировки, состояния мастеров, реквизиты, JSON errors, переименование WAITING в PENDING. Старые реквизиты из Setting переносятся; существующие клиенты/оплаты/чеки сохраняются. Prisma @map сохраняет прежние имена колонок reviewedBy, receiptFileType, assignedTo, entity.

Единственный HTTP endpoint — GET /health. Ответ включает status, database, tokenConfigured, timestamp. При недоступности PostgreSQL — 503; остальные пути и методы — 404. Веб-панели и webhook нет; Telegram используется через polling.

Worker сохраняет Telegram update и offset в БД, обрабатывает последовательно, удерживает lease и корректно завершает процесс. Старые OutboxJob не исполняются этой административной версией. Непредвиденная ошибка старта завершает процесс с ненулевым кодом для Railway restart.

## Railway

1. Подключите этот GitHub репозиторий к Railway.
2. Добавьте PostgreSQL и свяжите DATABASE_URL с сервисом.
3. Задайте TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_ID, необязательный TELEGRAM_BOT_USERNAME, NODE_ENV=production.
4. railway.json использует Dockerfile, pre-deploy npm run db:migrate, start npm start, health /health, restart ON_FAILURE.
5. Выполните npm run db:seed один раз через Railway CLI/SSH в окружении сервиса, если нужны демонстрационные направления и DRAFT курсы.
6. Откройте личный чат с ботом и отправьте /admin.

Dockerfile собирает Node.js 22 приложение. Состояние хранится в PostgreSQL; локальные JSON/SQLite/медиа-файлы для бизнеса не используются. Live деплой и права в реальном Telegram должны проверяться с вашими учётными данными.

## Проверки

```sh
npm run lint
npm run typecheck
npm run test:integration
npm run build
npm run test:http
npm audit
```

test:integration поднимает отдельный PostgreSQL 16, проверяет перенос legacy данных, применяет миграции, выполняет seed дважды и запускает unit + integration tests. Telegram API заменён mock. Пользовательский DATABASE_URL для этих тестов не используется.

test:http запускает скомпилированный worker без токена, проверяет /health и отсутствие web routes, перезапускает процесс и проверяет сохранность мастера. npm test без TEST_DATABASE_URL запускает только unit tests; интеграционные пропускаются.

Реальный getMe, взаимодействие с ботом в Telegram, отправка фото/видео/чеков и createChatInviteLink требуют действующего TELEGRAM_BOT_TOKEN и прав администратора канала. Mock тесты не подтверждают эти внешние права.
